# Страница «Наша команда» — дизайн

## Цель

Создать на `/teams/` самостоятельную страницу команды в классической WordPress-теме Promokodiki. Контент должен редактироваться через ACF без изменений шаблона и повторять информационную структуру страницы Pepper.ru/team.

## Границы

- Страница показывает вступление и произвольное число секций команд.
- Каждая секция содержит заголовок, текстовое описание и список сотрудников.
- Сотрудник отображается только круглой аватаркой. Визуальное имя, должность, биография и социальные ссылки отсутствуют.
- Клик по аватарке ведёт на необязательную ссылку сотрудника. Если ссылка не заполнена, аватарка остаётся неинтерактивным изображением.
- Пустые секции и записи сотрудников не выводятся. Демонстрационные данные и заглушки не используются.

## Архитектура

Шаблон `page-teams.php` будет выбран вручную для страницы `/teams/`, как существующий шаблон FAQ. Он подключает header/footer и передаёт идентификатор страницы в изолированный модуль `inc/teams-page.php`.

Модуль регистрирует на `acf/init` локальную ACF-группу, привязанную только к шаблону «Наша команда», и предоставляет функции получения и безопасного рендеринга данных. Отсутствие ACF не приводит к фатальной ошибке: страница рендерит лишь стандартную оболочку без контентных секций.

## ACF-модель

На уровне страницы:

- `teams_page_introduction` — WYSIWYG-вступление под заголовком страницы; необязательное.
- `teams_page_sections` — repeater; необязательный.

В каждой секции `teams_page_sections`:

- `title` — обязательный текстовый заголовок;
- `description` — необязательный WYSIWYG-текст;
- `members` — repeater.

В каждом участнике `members`:

- `name` — обязательное текстовое поле, применяется только в `alt` у изображения и в доступном названии ссылки;
- `photo` — обязательное поле изображения, возвращающее массив ACF;
- `url` — необязательное поле URL.

## Рендеринг и доступность

- Заголовок страницы берётся из `the_title()` и экранируется WordPress-функциями.
- WYSIWYG-поля выводятся через `wp_kses_post()`.
- Текстовые данные, атрибуты и URL экранируются через `esc_html()`, `esc_attr()` и `esc_url()`.
- При наличии URL аватарка располагается внутри ссылки с доступным именем сотрудника; при отсутствии — выводится `img` с тем же осмысленным `alt`.
- Декоративных дубликатов изображения нет; у изображений сохраняются заданные WordPress ширина и высота, если они доступны.

## Вёрстка

Страница использует существующие `header.php`, `footer.php`, контейнеры темы и хлебные крошки. Новый неймспейс CSS `teams-page` задаёт отступы, типографику, сетку аватарок и видимый фокус ссылок.

Аватарки имеют одинаковую круглую форму через `object-fit: cover`. Сетка автоматически переносит элементы на узких экранах; горизонтальная прокрутка и JavaScript не требуются. Цвета, шрифты и радиусы берутся из текущих CSS-переменных темы.

## Проверка

- Добавить автономный PHP-тест рендер-функции по образцу `tests/faq-page.php`.
- Проверить вывод заголовка, вступления, секции, фото с `alt`, интерактивной и неинтерактивной аватарки, а также скрытие пустых данных.
- Запустить PHP lint для изменённых PHP-файлов и тест страницы.
- Открыть `/teams/` с назначенным шаблоном и проверить desktop/mobile в браузере.

# SEO-импорт и проверка третьего этапа

Источник сохранён в `wp-content/plugins/promokodiki-seo-import/data/seo-pages.csv`. Импорт работает только по точному названию после нормализации регистра и пробелов. Он не создаёт страницы и рубрики, не меняет slug и не объединяет похожие объекты.

## Порядок выпуска

1. Установить и активировать `promokodiki-seo-import` вместе с Yoast SEO.
2. Создать полный backup базы средствами хостинга.
3. Выполнить `wp promokodiki seo dry-run` и сохранить JSON-отчёт.
4. Проверить списки `missing` и `stale`. На локальной базе 14 сентября 2026 года найдены 114 строк; отсутствуют «Приложения» и «Другое», сезонная строка «Новогодние промокоды» пропущена.
5. Применить данные: `wp promokodiki seo apply --backup-file=/absolute/path/full-database.sql`.
6. Проверить главную, `/discounts/`, одну рубрику, один магазин и один промокод: H1, title, description, canonical и robots.
7. Проверить, что ссылка «В каталог» использует production-домен. До выпуска в кеше production обнаружена ссылка на `promokodiki.wp.local`; после установки нужно очистить WP Rocket и CDN.

Перед изменением полей команда создаёт JSON-копию в `wp-content/uploads/promokodiki-seo-backups/` и хранит последние пять копий. Откат: `wp promokodiki seo rollback --file=/absolute/path/seo-fields-YYYYmmdd-HHMMSS.json`. После применения и отката запускается переиндексация Yoast и очистка WP Rocket.

Индивидуальные SEO-поля рубрик сохраняются в штатной опции Yoast `wpseo_taxonomy_meta`. Обычный WordPress `termmeta` Yoast 26.6 для title и description рубрик не использует.

Исправлены четыре очевидные ошибки источника: «скопруйте», «скидки разработку», «Актуальные скидка» и «промокоды на электрики». Длинные title и description сохранены без автоматического сокращения.

## Индексация

- Параметры поиска и фильтров `s`, `paf_category`, `paf_brand`, `paf_sort`, `paf_popular`, `paf_page` получают `noindex, follow` и canonical без параметров.
- Обычная пагинация сохраняет self-canonical и остаётся индексируемой.
- Пустая рубрика без активных предложений и редакционного описания получает `noindex, follow`; правило снимается автоматически после появления контента.
- Служебная рубрика Telegram получает собственные title и description и не наследует общий шаблон категорий.

## Производительность

Проверяются пять типов production-страниц в mobile и desktop: главная, скидки, рубрика, магазин, промокод. Фиксируются Performance score, LCP, CLS, TBT и INP, когда доступно полевое значение. 14 сентября 2026 года публичный PageSpeed API вернул `429 RESOURCE_EXHAUSTED`, поэтому числовой baseline нужно снять повторно после восстановления квоты; выпуск не должен подменять отсутствующие измерения оценочными числами.

Карточки теперь используют responsive attachment markup с размерами. Первое потенциальное LCP-изображение загружается eager с `fetchpriority=high`, последующие — lazy. Скрипт модального окна подключается только на страницах с карточками, скрипт Telegram-слайдера — только на главной.

## Диагностика и CI

Telegram и Admitad хранят последние 30 агрегированных запусков. Видны источник, время последнего успеха, краткая ошибка, полученные/созданные/обновлённые/отклонённые/деактивированные элементы и длительность. Telegram считается устаревшим через 6 часов, Admitad — через два настроенных интервала; до первого запуска выводится `never_run`.

GitHub Actions проверяет PHP 8.1 и 8.4, JS, Python-worker, поведение PHP в disposable WordPress и Chromium на 390×844 и 1440×900. Сценарии браузера проходят цепочки «меню → магазин → код → закрытие» и «скидки → сортировка → ещё → назад» на детерминированных фикстурах.

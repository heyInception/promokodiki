# Магазины и Admitad: инструкция администратора

Эта инструкция описывает настройку интеграции, привязку магазинов к кампаниям Admitad, автоматическое заполнение описаний и контактов, работу с логотипами и генерацию партнёрских ссылок для `.promocodes__shop-site`.

## 1. Что изменяется на сайте

Интеграция работает с существующими терминами таксономии `shops_category`. Она не создаёт магазины автоматически и не связывает их по похожему названию: для автоматизации каждому магазину нужен точный `admitad_campaign_id`.

На публичной странице магазина:

- описание берётся из ручной версии или очищенного описания Admitad;
- выводятся рейтинг и данные магазина, если они доступны;
- в `.promocodes__shop-site` отображается обычный домен магазина, но переход может идти через Admitad;
- изображения в карточках промокодов `.promocodes__imgs` не изменяются;
- публичная страница никогда не обращается к Admitad API.

На `/shops/` поиск выполняется без перезагрузки страницы. Магазины, которые не соответствуют запросу, скрываются; пустая буквенная группа скрывается вместе с `.alphabetical__name`. Совпавшая часть названия подсвечивается только внутри `.alphabetical__list-item` цветом `#fe1477`.

## 2. Права доступа

Настройка интеграции, изменение Campaign ID и запуск очередей требуют права `manage_admitad_automation`. По умолчанию оно выдаётся администратору WordPress.

Если нужные элементы интерфейса отсутствуют, сначала проверьте роль пользователя. Не выдавайте это право редакторам, которым не нужно управлять подключением и глобальной синхронизацией.

## 3. Настройка подключения Admitad

Откройте **Промокоды → Настройки** и заполните:

- **Client ID**;
- **Client secret**;
- **Website ID** — ID рекламной площадки Admitad, для которой загружаются кампании и купоны.

После сохранения нажмите **Проверить подключение**. Значение Client secret повторно не выводится: пустое поле при следующем сохранении означает «не менять существующий секрет».

### Рекомендуемое хранение credentials

На production предпочтительно задать credentials константами в `wp-config.php`:

```php
define( 'PROMOKODIKI_ADMITAD_CLIENT_ID', 'client-id' );
define( 'PROMOKODIKI_ADMITAD_CLIENT_SECRET', 'client-secret' );
define( 'PROMOKODIKI_ADMITAD_WEBSITE_ID', 'website-id' );
```

Когда константа определена, соответствующее значение нельзя изменить через панель WordPress.

### Scope для deeplink

Плагин запрашивает следующие права OAuth:

```text
advcampaigns websites coupons coupons_for_website public_data advcampaigns_for_website deeplink_generator
```

После установки обновлённой версии нужно получить новый токен, содержащий `deeplink_generator`. Интеграция использует `client_credentials`, поэтому отдельного браузерного подтверждения нет:

1. Откройте **Промокоды → Настройки**.
2. Нажмите **Проверить подключение** — сохранённый токен будет обновлён.
3. Запустите генерацию одной ссылки и проверьте её статус.

Если API возвращает HTTP 403, проверьте, доступен ли генератор deeplink вашему приложению и площадке в Admitad. При такой ошибке сайт продолжит использовать прямую ссылку магазина.

## 4. Первый запуск

Рекомендуемый порядок после установки или обновления:

1. Сделайте резервную копию базы данных и медиатеки.
2. Настройте credentials и проверьте подключение.
3. Откройте **Промокоды → Синхронизация**.
4. Нажмите **Обновить справочники** и дождитесь завершения задачи. Это загружает локальный справочник кампаний и категорий Admitad.
5. Откройте **Промокоды → Магазины без связи** и исправьте отсутствующие или ошибочные Campaign ID.
6. Вернитесь в **Синхронизацию**, в блоке «Обогащение страниц магазинов» выполните **Предварительный просмотр**.
7. Проверьте количества связанных магазинов, новых и переиспользуемых логотипов, затем нажмите **Запустить первое заполнение**.
8. На странице **Магазины без связи** выполните предварительный просмотр deeplink и поставьте их в очередь.
9. Проверьте несколько страниц `shops-category` и страницу `/shops/`.

Сначала всегда обновляйте справочники: неизвестный локальной базе Campaign ID нельзя безопасно назначить магазину.

## 5. Привязка магазина к кампании

### Через список проблемных магазинов

Откройте **Промокоды → Магазины без связи**. В таблицу попадают только существующие магазины со следующими проблемами:

| Причина | Что означает | Что сделать |
|---|---|---|
| Campaign ID не указан | У магазина отсутствует связь | Найти кампанию и указать её ID |
| Campaign ID некорректен | Значение пустое, нечисловое или меньше 1 | Заменить на положительный числовой ID |
| Кампании нет в локальном справочнике | Справочники устарели либо ID ошибочен | Обновить справочники и проверить ID |
| Campaign ID используется несколько раз | Одна кампания назначена нескольким магазинам | Оставить связь только у правильного магазина |

Кнопка **Найти кампанию по названию** открывает локальный справочник компаний с поиском. После выбора кампании скопируйте её Campaign ID, вернитесь к магазину и нажмите **Связать**.

Сохранение выполняет только локальные операции:

- проверяет существование кампании и уникальность ID;
- сохраняет `admitad_campaign_id`;
- переносит уже загруженный профиль кампании;
- заполняет только пустые контактные поля;
- ставит deeplink в фоновую очередь.

Запрос к Admitad API непосредственно при нажатии **Связать** не выполняется.

### Через редактор магазина

Откройте **Промокоды → Магазины → Изменить магазин** и найдите секцию **Описание из Admitad**. Поле **Campaign ID Admitad** видно непосредственно в редакторе термина.

Новое значение принимается только тогда, когда кампания есть в локальном справочнике и не назначена другому магазину. Если ID не сохраняется, обновите справочники и проверьте страницу «Магазины без связи».

## 6. Описание магазина

В редакторе магазина доступны два независимых варианта описания.

### Исходное описание Admitad

Это автоматически обновляемая версия. Перед сохранением интеграция:

- удаляет элементы `<a>` вместе с текстом внутри ссылок;
- удаляет изображения, формы, iframe, скрипты и другой неподдерживаемый HTML;
- удаляет служебные разделы для веб-мастеров, партнёров и правил трафика;
- оставляет только абзацы, заголовки, списки, жирное и курсивное начертание.

Исходное описание показывается только для чтения и при следующей синхронизации может измениться.

### Описание для сайта

Это ручная редакционная версия. Синхронизация никогда её не перезаписывает.

- **Скопировать исходное** переносит очищенный текст Admitad в визуальный редактор.
- После копирования удалите лишние рекламные формулировки и сохраните магазин.
- **Сбросить ручную версию** удаляет ручное описание и возвращает автоматический вариант.

Приоритет вывода:

1. ACF-поле `shop_description`, если оно заполнено;
2. ручное описание для сайта;
3. очищенное исходное описание Admitad;
4. прежнее метаполе Admitad для обратной совместимости;
5. стандартное описание термина WordPress.

## 7. «О магазине» и рейтинг

Блок «О магазине» формируется из краткого описания профиля Admitad, если оно доступно. Ручное ACF-поле `about_shop` имеет приоритет над автоматическим значением.

Рейтинг используется только в диапазоне от 1 до 5. Приоритет:

1. ACF-поле `rating`;
2. рейтинг, сохранённый из Admitad;
3. блок рейтинга не выводится, если корректного значения нет.

Автоматический рейтинг не следует воспринимать как пользовательский рейтинг сайта: это справочное значение источника Admitad.

## 8. Контактные данные

В редакторе доступны поля:

- **Адрес магазина** (`shop_address`);
- **Телефон** (`shop_phone`);
- **Почта магазина** (`shop_email`);
- **Сайт** (`shop_website`).

Автоматическое заполнение работает консервативно:

- сайт берётся из структурированного `site_url` кампании;
- телефон и email сохраняются, только если в описании найден ровно один однозначный вариант;
- при нескольких вариантах поле не заполняется, а кандидаты показываются администратору;
- адрес не извлекается из свободного текста;
- уже заполненные поля никогда не перезаписываются автоматикой.

На публичной странице ACF-поля `address`, `phone`, `email` и `website` имеют приоритет над обычными метаполями WordPress.

## 9. Партнёрские ссылки Admitad

Генератор вызывает официальный endpoint:

```text
GET /deeplink/{website_id}/advcampaign/{campaign_id}/
```

В `ulp` передаётся прямой `site_url` магазина, а в `subid` — постоянная метка `shop_page`.

### Массовая генерация

На странице **Промокоды → Магазины без связи** находится блок **Партнёрские ссылки Admitad**.

1. Нажмите **Предварительный просмотр**.
2. Проверьте результат:
   - **Создать** — deeplink ещё отсутствует;
   - **Обновить** — изменился Website ID, Campaign ID или прямой URL;
   - **Без изменений** — сохранённая ссылка соответствует текущим данным;
   - **Не поддерживается** — API сообщил, что генерация недоступна;
   - **Некорректно** — отсутствует Campaign ID, Website ID или URL магазина.
3. Нажмите **Поставить в очередь**.

Очередь устраняет повторяющиеся ID и обрабатывает не более 20 магазинов за один запуск WP-Cron. Если элементы остаются, плагин планирует следующий пакет.

### Генерация для одного магазина

Откройте редактор магазина и нажмите **Перегенерировать** в строке **Deeplink Admitad**, затем сохраните термин. Магазин будет поставлен в ту же фоновую очередь.

### Приоритет ссылок на сайте

Для `.promocodes__shop-site` применяется порядок:

1. ручная партнёрская ссылка;
2. автоматический deeplink Admitad;
3. прямой URL магазина.

Пользователь видит домен прямого сайта, даже если `href` ведёт через Admitad. Ссылка открывается в новой вкладке и получает:

```html
rel="nofollow sponsored noopener noreferrer"
```

Временная ошибка API не удаляет ранее рабочий deeplink. Если автоматическая ссылка отсутствует или генерация не поддерживается, используется прямой URL.

## 10. Статусы deeplink

В редакторе магазина рядом со ссылкой показывается технический статус:

| Статус | Значение |
|---|---|
| `ready` | Ссылка успешно создана |
| `unsupported` | Кампания или OAuth-доступ не поддерживает генерацию |
| `error` | Временная или непредвиденная ошибка API |
| `invalid` | Не хватает Campaign ID, Website ID или URL магазина |
| пусто | Генерация ещё не запускалась |

При `error` сначала повторите генерацию позже. При `unsupported` проверьте scope `deeplink_generator`, доступ приложения и настройки кампании. При `invalid` исправьте исходные данные магазина.

## 11. Логотипы и защита медиатеки от переполнения

Интеграция не загружает изображение заново при каждой синхронизации. Для управляемых логотипов действуют правила:

- разрешены JPEG, PNG и WebP;
- максимальный размер — 2 МиБ;
- одинаковые файлы переиспользуются по SHA-256;
- SVG не сохраняется в медиатеку;
- при ошибке загрузки остаётся прежний рабочий логотип;
- автоматическая очистка касается только файлов, созданных этой интеграцией;
- используемые или изменённые вручную вложения не удаляются.

Перед удалением осиротевших логотипов:

1. Сделайте резервную копию медиатеки.
2. В **Промокоды → Синхронизация** запустите предварительный просмотр обогащения.
3. Проверьте количество и список кандидатов.
4. Только после проверки нажмите **Удалить показанные осиротевшие логотипы**.

Изображения внутри `.promocodes__imgs` остаются без изменений.

## 12. WP-Cron и ручной запуск

Для фоновой генерации используется событие:

```text
promokodiki_admitad_deeplink_batch
```

В локальном WordPress Studio его можно запустить вручную:

```powershell
studio wp cron event run promokodiki_admitad_deeplink_batch
```

На сервере с обычным WP-CLI:

```bash
wp cron event run promokodiki_admitad_deeplink_batch
```

Проверить наличие события:

```powershell
studio wp cron event list --fields=hook,next_run_relative | Select-String admitad_deeplink
```

Если очередь не выполняется автоматически, проверьте `DISABLE_WP_CRON`, системный cron и возможность WordPress выполнять loopback-запросы. Рекомендуемый production-вариант — системный вызов `wp cron event run --due-now` каждые 5 минут.

## 13. Проверка после настройки

Проверьте минимум три магазина: связанный с готовым deeplink, магазин без deeplink и магазин с ручной партнёрской ссылкой.

Для каждого магазина убедитесь, что:

- описание не содержит ссылок и служебного партнёрского текста;
- ручное описание сохраняется после повторной синхронизации;
- телефон, email и сайт выводятся корректно;
- адрес не появился автоматически из случайного текста;
- рейтинг находится в диапазоне 1–5;
- логотип не дублируется в медиатеке;
- текст ссылки показывает домен магазина;
- `href` соответствует ожидаемому приоритету;
- у ссылки присутствует `rel="nofollow sponsored noopener noreferrer"`;
- карточки промокодов и `.promocodes__imgs` не изменились.

На `/shops/` проверьте поиск на кириллице и латинице, очистку строки поиска, скрытие пустых буквенных групп и подсветку только названия магазина.

## 14. Диагностика типовых проблем

### Campaign ID не сохраняется

- Запустите **Промокоды → Синхронизация → Обновить справочники**.
- Убедитесь, что ID числовой и больше нуля.
- Проверьте, не используется ли он другим магазином.
- Найдите магазин на странице **Магазины без связи** — там будет указана точная причина.

### Описание не обновилось

- Проверьте, заполнено ли ручное описание или ACF `shop_description`: они имеют более высокий приоритет.
- Если нужна автоматическая версия, отметьте **Сбросить ручную версию** и сохраните магазин.
- Обновите справочники и повторите обогащение страниц магазинов.

### Телефон или email не заполнились

- Автоматика ничего не записывает, если найдено несколько кандидатов.
- Посмотрите строку **Кандидаты из Admitad** в редакторе магазина и выберите значение вручную.
- Уже заполненное поле намеренно не перезаписывается.

### Deeplink имеет статус `unsupported`

- Обновите OAuth-токен через **Проверить подключение**.
- Проверьте наличие scope `deeplink_generator`.
- Убедитесь, что кампания подключена к указанному Website ID.
- Если Admitad не разрешает генерацию для кампании, используйте ручную партнёрскую или прямую ссылку.

### Deeplink имеет статус `error`

- Не удаляйте старую ссылку: система сохраняет последний рабочий вариант.
- Повторите операцию позже — возможны HTTP 429 или временная ошибка Admitad.
- Проверьте **Промокоды → Диагностика** и последние запуски.

### Очередь не уменьшается

- Запустите cron-событие вручную.
- Проверьте системный cron и `DISABLE_WP_CRON`.
- Убедитесь, что в очереди нет магазинов с отсутствующим сайтом или Campaign ID.

## 15. Безопасный откат

Если партнёрские переходы работают неправильно:

1. Заполните **Ручную партнёрскую ссылку** корректным URL — она сразу получит высший приоритет.
2. Либо оставьте ручное поле пустым и удалите/не генерируйте автоматический deeplink: сайт использует прямой URL.
3. Не удаляйте Campaign ID, если описание, рейтинг и логотип должны продолжать обновляться.
4. Перед массовым изменением или очисткой сделайте резервную копию.

## 16. Техническая памятка

Основные метаполя термина:

| Поле | Назначение |
|---|---|
| `admitad_campaign_id` | Связь магазина с кампанией Admitad |
| `_admitad_shop_source_description` | Очищенное автоматическое описание |
| `_admitad_shop_manual_description` | Ручное описание для сайта |
| `shop_address`, `shop_phone`, `shop_email`, `shop_website` | Редактируемые контакты |
| `_admitad_shop_manual_affiliate_url` | Ручная партнёрская ссылка |
| `_admitad_shop_deeplink` | Автоматическая ссылка Admitad |
| `_admitad_shop_deeplink_status` | Состояние генерации |
| `_admitad_shop_deeplink_fingerprint` | Контроль актуальности ссылки |
| `_admitad_shop_contact_hints` | Неоднозначные кандидаты телефона и email |

Не изменяйте служебные поля с подчёркиванием напрямую в базе без резервной копии. Для обычной работы используйте редактор магазина и административные очереди.

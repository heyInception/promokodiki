# Promokodiki

## Страница FAQ

Страница `/faq/` использует шаблон `page-faq.php` и ACF Pro. Контент редактируется на самой странице через поля:

- вступление;
- разделы FAQ → вопросы и WYSIWYG-ответы;
- заголовок и описание сайдбара;
- заголовок, текст, ссылку и подпись CTA.

На странице есть семантическая `FAQPage`-разметка, плавный аккордеон (одновременно открывается один ответ) и sticky-сайдбар с якорной навигацией по разделам. На мобильных сайдбар превращается в раскрывающийся блок «Содержание».

## Обновление: магазины и Admitad

- Каталог `/shops/` получил быстрый поиск: пустые буквенные группы скрываются, а совпадения подсвечиваются только в названии магазина.
- Для магазинов добавлены очищаемые описания Admitad, отдельное ручное описание, безопасное заполнение контактов и вывод рейтинга.
- В панели WordPress появились видимый `Campaign ID Admitad`, страница «Магазины без связи» и быстрый переход к исправлению привязки.
- Ссылка на сайт магазина поддерживает ручный affiliate URL и автоматический deeplink Admitad; генерация выполняется фоновыми пакетами через WP-Cron.
- Подробное руководство: [docs/shop-admitad-editor-guide.md](docs/shop-admitad-editor-guide.md).

## Обновление: страница «Скидки»

Страница «Скидки» переведена на единый серверный и AJAX-контур плагина `promokodiki-ajax-filter`.

- В `tabs__nav` доступны сортировки: сначала новые, популярные за неделю, скоро закончатся и сначала старые.
- Сортировка и кнопка «Показать ещё» обновляют карточки через AJAX без перезагрузки страницы; базовые GET-ссылки продолжают работать без JavaScript.
- Выбранное состояние сохраняется в URL и корректно восстанавливается кнопками браузера «Назад» и «Вперёд».
- При ошибке запроса текущая выдача сохраняется, состояние интерфейса откатывается к последнему успешному ответу, а повтор запроса не смешивает разные сортировки.
- В выдачу скидок попадают только активные и неистёкшие предложения. Популярность рассчитывается по кликам за последние семь дней с безопасным переходом на общий счётчик при отсутствии недельных данных.
- При отключённом плагине тема сохраняет серверную сортировку и вывод скидок.
- Устаревшие inline-скрипты удалены из Footer; логика интерфейса и навигации перенесена в отдельные подключаемые файлы.

Архитектурные решения и границы реализации описаны в [спецификации](docs/superpowers/specs/2026-08-04-discounts-ajax-sorting-design.md) и [плане реализации](docs/superpowers/plans/2026-08-04-discounts-ajax-sorting.md).

## Обновление: AJAX-фильтр промокодов

Добавлен собственный плагин `promokodiki-ajax-filter`, который заменяет Filter Everything и обновляет выдачу без перезагрузки страницы.

- На главной доступны одиночные фильтры категории и бренда, сортировка и режим «Популярное за неделю».
- Категории и бренды взаимозависимы: каждый список содержит только совместимые варианты с активными промокодами.
- «Популярное за неделю» сбрасывает остальные условия и работает как отдельный режим.
- На странице категории выводятся только текущая категория и её подкатегории; для категории без потомков список скрывается.
- На странице магазина показываются все связанные бренды; если доступен только один бренд, список скрывается.
- Кнопка «Показать ещё» добавляет следующую порцию карточек через AJAX.
- Во время каждого запроса показывается лоадер, при этом текущие карточки остаются на экране.
- Состояние фильтров сохраняется в URL и корректно восстанавливается кнопками браузера «Назад» и «Вперёд».
- В панели WordPress доступны настройки фильтра, сортировки, размера страницы и поведения выдачи.
- Добавлены подсчёт популярности по кликам, кеширование доступных вариантов и совместимость с WP Rocket, включая исправление URL Background CSS в Windows.

## Интерактивные промокоды

В разделе «Промокоды → AJAX-фильтр» доступны настройки срока badge «Новое», минимального недельного порога «Популярное», периода защиты от повторного применения и поведения кнопок истекших карточек. Значение `0` для периода защиты учитывает каждый переход. Применение засчитывается после подтверждения перехода в модальном окне; реакции посетителя можно менять между лайком и дизлайком.

Что изменилось:

- единая карточка промокода используется в AJAX-выдаче, поиске и кастомном выводе;
- бренды на карточках ведут на соответствующие архивные страницы;
- статусы «Истекло», «Новое» и «Популярное» вычисляются на сервере с единым приоритетом;
- переход в магазин проходит через модальное окно, копирует код и учитывает применение;
- повторные применения контролируются по настраиваемому интервалу для анонимного посетителя;
- лайк и дизлайк стали одной сменяемой реакцией, защищённой серверным идентификатором;
- схема БД автоматически обновляется для хранения применений и голосов.
- Filter Everything и Filter Everything Pro должны оставаться выключенными.

Активация:

```powershell
studio wp plugin activate promokodiki-ajax-filter
```

WordPress-тема и плагин синхронизации промокодов с Admitad. Репозиторий содержит только пользовательский код: ядро WordPress, база, загрузки и сторонние плагины намеренно исключены.

## Архитектура данных

- `promocode` — единственный тип записи для предложений.
- `promocode_category` — тематические рубрики.
- `shops_category` — магазины; стабильный Admitad campaign ID хранится в term meta `admitad_campaign_id`.
- `/promocodes/` — архив промокодов, `/shops/` — каталог магазинов, `/shops-category/{slug}/` — предложения конкретного магазина.
- Старый CPT `shops` и таксономия `shop_coupons` не используются.

## Локальный запуск

Проект разработан в [WordPress Studio](https://developer.wordpress.com/studio/). После импорта сайта:

```powershell
studio start --skip-browser
studio wp plugin activate admitad-coupons
studio wp theme activate promokodiki
studio wp rewrite flush
```

В обычном WordPress-хостинге используйте те же команды без префикса `studio`.

## Настройка Admitad

После публикации старые credentials необходимо отозвать в Admitad. Новые значения задаются либо на странице **Промокоды → Admitad**, либо константами в неотслеживаемом `wp-config.php`:

```php
define( 'PROMOKODIKI_ADMITAD_CLIENT_ID', 'replace-locally' );
define( 'PROMOKODIKI_ADMITAD_CLIENT_SECRET', 'replace-locally' );
define( 'PROMOKODIKI_ADMITAD_WEBSITE_ID', 'replace-locally' );
```

Проверка соединения не показывает токен или secret. Синхронизация запускается дважды в день через WP-Cron либо вручную:

```powershell
studio wp admitad import
```

Импорт обрабатывает API постранично, блокирует параллельные запуски и обновляет запись по `admitad_coupon_id`, не создавая дублей.

## Миграция старой базы

Сначала выполните анализ:

```powershell
studio wp admitad migrate --dry-run
```

Перед выполнением обязателен непустой backup-файл:

```powershell
studio export backups/pre-migration.sql --mode db
studio wp admitad migrate --execute --yes --backup="backups/pre-migration.sql"
```

Команда переносит метаданные, комментарии и таксономии в канонические записи, затем безвозвратно удаляет дубли. Итоговый отчёт сохраняется в option `admitad_last_migration_report`.

Для восстановления локального сайта создайте новый сайт Studio и импортируйте сохранённый `.sql`/полный `.zip`. На production сначала проверьте процедуру восстановления средствами хостинга.

## Автоматизация Admitad

Плагин **Promokodiki Admitad Sync** автоматически:

- синхронизирует купоны, рекламные кампании и справочники Admitad;
- связывает стабильные ID категорий и кампаний с существующими рубриками сайта;
- классифицирует купоны по структурированным данным, профилям компаний и безопасным фразовым правилам;
- отправляет неизвестные значения, низкую уверенность, конфликты и подозреваемые дубли в очередь проверки;
- сохраняет ручные правки текста и рубрик абсолютными редакционными блокировками;
- ведёт историю изменений и поддерживает `preview → apply → rollback`;
- выполняет пакетные задачи через WP-Cron без блокирующих задержек.

Иерархия `promocode_category` остаётся редакционной: плагин не создаёт, не переименовывает, не перемещает и не удаляет рубрики. Подозреваемые дубли никогда не объединяются автоматически.

### Первичная настройка

1. Активируйте плагин и откройте **Промокоды → Настройки**.
2. Укажите `client_id`, `client_secret` и `website_id`. Для production предпочтительны константы `PROMOKODIKI_ADMITAD_CLIENT_ID`, `PROMOKODIKI_ADMITAD_CLIENT_SECRET` и `PROMOKODIKI_ADMITAD_WEBSITE_ID` в `wp-config.php`.
3. В разделе **Маппинг категорий** свяжите ID Admitad только с уже существующими рубриками.
4. Проверьте **Компании**, **Правила** и **Очередь проверки**. Для маркетплейсов задайте разрешённый набор рубрик; рубрика по умолчанию необязательна.
5. В **Диагностике** убедитесь, что схема базы, расписание и конфигурация готовы.

Secret и access token не выводятся обратно в административной панели или диагностическом экспорте.

### Безопасная миграция старого маппинга

Сначала создайте и проверьте резервную копию базы, затем выполните только анализ:

```powershell
studio wp admitad automation-migrate --dry-run
```

После проверки отчёта миграцию можно запустить явно:

```powershell
studio wp admitad automation-migrate --execute --backup="C:\backups\before-admitad.sql" --yes
```

Команда копирует данные пакетами и не удаляет старые таблицы. Неоднозначные компании отправляются в очередь, конфликтующие фразы получают статус `conflict`, небезопасные короткие фрагменты приостанавливаются.

Команда `studio wp admitad migrate` из раздела выше решает другую задачу — объединение старых дублей записей — и не должна запускаться вместо `automation-migrate`.

### Проверка перед массовым применением

1. Сформируйте контрольную выборку из 150 купонов в разделе **История и откат**.
2. Проверьте ожидаемые рубрики и метрики: точность high-confidence не ниже 95%, покрытие рубриками конкретнее `other` не ниже 85%, сохранность ручных блокировок 100%, назначений вне профиля компании 0%.
3. Создайте preview, проверьте пары «было → станет» и только затем выполните apply.
4. При необходимости восстановите исходные назначения по UUID того же снимка.
5. Запустите две последовательные синхронизации: второй проход должен преимущественно вернуть `unchanged`, не создавать дубли и не менять заблокированные данные.

### WP-Cron и эксплуатация

В WP Crontrol должны отображаться:

- `promokodiki_admitad_coupon_sync`;
- `promokodiki_admitad_reference_sync`;
- `promokodiki_admitad_reconcile`;
- `promokodiki_admitad_retention`.

WP-Cron является поддерживаемым базовым режимом. Если хостинг предоставляет системный CRON, можно дополнительно выполнять `wp cron event run --due-now` каждые пять минут. Состояние запусков, очереди, блокировок и ошибки OAuth доступны в разделах **Обзор**, **Синхронизация** и **Диагностика**.

Полный эксплуатационный регламент, восстановление и команда запуска тестов: [docs/admitad-automation-operations.md](docs/admitad-automation-operations.md).

# Карточки промокодов и Telegram-подборка — дизайн

## Цель

Исправить единый пользовательский сценарий промокодов на главной, в каталогах и на внутренней странице: корректно показывать код и срок действия, надёжно открывать магазин, учитывать переходы и реакции без блокировки пользователя. До появления настоящей Telegram-интеграции блок «Топ промокодов из Telegram» должен формировать правдоподобную общую подборку из локального каталога.

## Источник истины

Плагин `promokodiki-ajax-filter` остаётся владельцем серверных AJAX-действий применения промокода и голосования. Тема отвечает за разметку карточек и модалки, браузерные взаимодействия и рендер Telegram-подборки. Старые параллельные обработчики темы и клиентские сценарии удаляются.

Для фронтенда используется один локализованный объект конфигурации с `admin-ajax.php` и nonce действия `promokodiki_filter_frontend`. Глобальные переменные, напечатанные вручную в `wp_head`, больше не нужны.

## Карточка и модальное окно

Каждый экземпляр предложения передаёт браузеру одинаковый набор данных: ID записи, URL магазина, наличие и значение кода, дату окончания, описание, логотип, число применений, текущие счётчики реакций и реакцию текущего анонимного посетителя.

- Предложение с кодом показывает кнопку «Посмотреть код» или «Применить код». Кнопка открывает общую модалку.
- При открытии модалки код по возможности автоматически копируется. Отказ Clipboard API не мешает работе модалки.
- Ручная кнопка копирования использует современный Clipboard API с совместимым запасным способом и временно показывает «Скопировано» после успеха.
- Кнопка «Перейти с промокодом» открывает URL магазина в новой вкладке. Исходная модалка остаётся открытой.
- Предложение без кода показывает «Перейти в магазин». Эта кнопка никогда не открывает модалку и сразу открывает URL магазина в новой вкладке.
- Для прямого перехода и перехода из модалки учёт применения отправляется в фоне. Ошибка AJAX не задерживает, не отменяет переход и не показывает пользователю техническую ошибку.
- После успешного ответа число применений синхронизируется во всех экземплярах предложения на текущей странице.
- Дата окончания показывается в формате `дд.мм.гггг`. Если даты нет, выводится «Бессрочно».
- Истёкшее предложение остаётся видимым со статусом «Истёк», но не позволяет открыть модалку, скопировать код или перейти в магазин. Вместо действия показывается неактивное «Промокод истёк».

Одинаковые правила действуют на главной, в результатах фильтрации и поиска, в Telegram-блоке и на внутренней странице промокода.

## Реакции

Для одного промокода посетитель хранит ровно одну реакцию: `like` или `dislike`. Повторный клик по уже выбранной реакции идемпотентен. Клик по противоположной реакции переносит голос и корректирует оба счётчика.

Выбранная реакция восстанавливается после перезагрузки по first-party visitor ID. После ответа сервера новые счётчики и активное состояние синхронизируются во всех экземплярах того же промокода на странице, включая Telegram-блок.

Старый AJAX-вызов `handle_promocode_like`, старый вызов `increment_promocode_used` и отдельная повторная инициализация обработчиков Telegram-карточек удаляются. Все карточки используют делегированные обработчики единого клиента.

## Имитация Telegram-подборки

Заголовок «Топ промокодов из Telegram» сохраняется без дополнительной подписи. Количество карточек продолжает задаваться существующей настройкой.

Кандидатами являются только опубликованные, активные и неистёкшие предложения. Допускаются предложения с кодом и акции без кода, но предложения с кодом получают приоритет.

Каждые три часа сервер создаёт один общий для всех посетителей снимок ID. Отбор использует:

1. применения за последние семь дней;
2. сумму лайков и дизлайков как показатель обсуждаемости;
3. свежесть публикации;
4. бонус за наличие промокода.

Если есть новое предложение, опубликованное за последние семь дней, один слот резервируется для него. Остальные элементы выбираются из верхней части взвешенного рейтинга с детерминированной ротацией для текущего трёхчасового окна. Если пул позволяет, новый снимок не должен полностью повторять предыдущий.

Снимок создаётся и хранится на сервере. Посетитель получает готовую подборку и время следующего окна; `localStorage` не является источником истины. По окончании таймера браузер запрашивает актуальный снимок. Публичный запрос защищён nonce и не может произвольно сдвигать глобальное окно обновления.

## Ошибки и безопасность

- Все AJAX-запросы используют nonce `promokodiki_filter_frontend`.
- Сервер валидирует опубликованный тип записи `promocode` и берёт внешний URL только из метаданных записи.
- ID, реакции и остальные входные данные санитизируются; HTML и атрибуты экранируются средствами WordPress.
- Новая вкладка открывается синхронно с пользовательским кликом, чтобы блокировщик всплывающих окон не зависел от ответа AJAX.
- При недоступности AJAX основное действие пользователя всё равно выполняется.

## Проверки

PHP-тесты покрывают выбор кандидатов, стабильность снимка внутри трёхчасового окна, ротацию между окнами, новый слот, исключение неактивных и истёкших предложений, а также восстановление реакции посетителя.

JavaScript-тесты покрывают открытие модалки только для предложений с кодом, прямой переход без модалки, неблокирующий учёт, дату и «Бессрочно», недоступные действия истёкшей карточки, копирование и синхронизацию реакций/счётчика применений.

Интеграционные проверки подтверждают единый nonce, отсутствие старых AJAX-действий и корректную разметку карточек во всех контекстах.

# Магазины: редактура Admitad, несвязанные магазины и Deeplink

## Цель

Расширить существующее обогащение `shops_category`: дать администратору безопасно редактировать импортированное описание и контакты, быстро связывать термы с кампаниями Admitad, генерировать партнёрную ссылку для блока «Сайт магазина» и улучшить поиск на `/shops/`.

## Общие ограничения

- Публичные страницы никогда не обращаются к Admitad API.
- Автоматическая связь выполняется только по точному числовому `admitad_campaign_id`; сопоставления по названию нет.
- Новые термы магазинов из кампаний автоматически не создаются.
- Ручные значения не перезаписываются синхронизацией.
- Доступ к новым административным операциям требует `manage_admitad_automation`, nonce и серверной валидации.
- `template-parts/promocode-card.php` и партнёрные ссылки самих промокодов не изменяются.

## 1. Поиск на `/shops/`

Клиентский поиск продолжает работать по уже отрендеренному активному каталогу:

- несовпадающие `.alphabetical__list-item` скрываются;
- группа `.alphabetical__list` вместе с `.alphabetical__name` скрывается, когда в ней не осталось совпадений;
- совпавшая часть текста только внутри `.alphabetical__list-item` оборачивается в безопасный `<mark>`;
- цвет совпадения — `#fe1477`, фон отсутствует;
- `.alphabetical__name` не подсвечивается;
- поиск нечувствителен к регистру и поддерживает кириллицу;
- исходное название хранится отдельно и полностью восстанавливается при очистке запроса;
- серверный `?s=` остаётся fallback без JavaScript.

## 2. Очистка и версии описания

Для каждого связанного магазина хранятся две независимые версии:

1. Очищенное исходное описание Admitad. Оно обновляется при синхронизации.
2. Ручное «Описание для сайта». Оно никогда не перезаписывается API.

На публичной странице используется ручная версия, если она непустая; иначе — очищенная актуальная версия Admitad; затем стандартное описание WordPress как последний fallback.

Очиститель:

- удаляет элемент `<a>` вместе со всем его содержимым;
- удаляет `script`, `style`, `iframe`, формы, элементы управления, изображения и исполняемые атрибуты;
- удаляет партнёрские/веб-мастерские служебные разделы по существующим правилам summary-очистки;
- разрешает только абзацы, заголовки, списки, `strong`, `em` и безопасные текстовые переносы;
- не разрешает ссылки даже в ручной версии редактора.

Очистка ручной версии означает явный возврат к автоматической очищенной версии.

## 3. Вкладка «Описание из Admitad» в редакторе термина

На экране `Промокоды → Магазины → Изменить магазин` добавляется административная вкладка/секция, доступная только по `manage_admitad_automation`.

Она содержит:

- видимое редактируемое поле `admitad_campaign_id`;
- очищенное исходное описание Admitad только для чтения;
- ограниченный визуальный редактор «Описание для сайта»;
- кнопки «Скопировать исходное в редактор» и «Сбросить ручную версию»;
- дату последней синхронизации;
- текущие и найденные контактные данные;
- исходный `site_url`, автоматический Deeplink, его статус и дату генерации;
- ручную партнёрную ссылку и кнопку перегенерации автоматической ссылки.

Сохранение полей использует term-edit hooks, capability check, nonce, sanitization и escaping. Минимальный аудит сохраняет дату, ID пользователя и источник значения (`manual`, `admitad`, `wordpress`); полная история версий не ведётся.

## 4. Контактные поля

Редактируемые поля магазина:

- адрес;
- телефон;
- email;
- сайт.

Синхронизация заполняет только пустые поля и никогда не перезаписывает непустое значение.

- Сайт берётся из структурированного `site_url` Admitad.
- Телефон и email извлекаются из описания только при однозначном формате и сохраняются лишь в пустые поля.
- Адрес автоматически не извлекается из свободного текста из-за риска ложного значения.
- Сомнительные телефон/email показываются администратору как подсказки и не сохраняются автоматически.
- Исчезновение значения в API не очищает сохранённое поле.

Публичный profile-helper сохраняет приоритет ACF/ручное значение → Admitad → WordPress независимо для каждого поля.

## 5. Страница «Магазины без связи»

В меню «Промокоды» добавляется отдельная страница для существующих термов `shops_category`. В неё входят магазины с одной из причин:

- Campaign ID отсутствует;
- ID не является положительным целым числом;
- кампания отсутствует в последнем локальном справочнике;
- один Campaign ID назначен нескольким термам.

Каждая строка показывает название, причину, быстрый поиск кампании в локальном справочнике, поле Campaign ID, защищённую кнопку сохранения и ссылку на полный редактор термина. Список пагинируется и фильтруется на сервере; он не перечисляет кампании, для которых на сайте отсутствует терм.

После валидного сохранения ID система без внешнего запроса:

- проверяет уникальность и наличие кампании в локальном справочнике;
- синхронизирует очищенное описание, рейтинг и пустые контакты;
- ставит логотип и Deeplink в существующую ограниченную очередь;
- удаляет строку из списка после успешного ответа.

Если ID неизвестен или дублируется, значение не сохраняется и выводится понятная ошибка.

## 6. Генератор Deeplink Admitad

Плагин запрашивает OAuth scope `deeplink_generator`; после обновления потребуется повторная авторизация.

API-клиент вызывает:

`GET /deeplink/{website_id}/advcampaign/{campaign_id}/`

Параметры:

- `ulp` — текущий исходный `site_url` магазина;
- `subid` — постоянное значение `shop_page`.

Генерация выполняется только в административном/фоновом процессе. Сохраняются:

- автоматический Deeplink;
- fingerprint из Website ID, Campaign ID и `site_url`;
- статус `ready`, `queued`, `unsupported` или `error`;
- дата последней попытки/успеха;
- безопасное сообщение ошибки без credentials.

Повторная генерация требуется только при изменении Website ID, Campaign ID или `site_url`. Временная ошибка не удаляет ранее рабочую ссылку. Если программа не подключена, не поддерживает Deeplink или API недоступен, используется обычный `site_url`.

Приоритет `href` в `.promocodes__shop-site`:

1. ручная партнёрная ссылка;
2. готовый автоматический Deeplink;
3. обычный `site_url`.

Видимый текст всегда остаётся обычным доменом магазина. Ссылка открывается в новой вкладке и имеет `rel="nofollow sponsored noopener noreferrer"`. Deeplink не применяется к внутренним ссылкам каталога, логотипам других магазинов или карточкам промокодов.

## 7. Пакетная работа и preview

Существующий экран обогащения расширяется счётчиками Deeplink:

- создать;
- обновить;
- без изменений;
- не поддерживается/ошибка.

Первое заполнение и регулярная синхронизация используют ограниченные возобновляемые пакеты. Ручная кнопка обрабатывает один магазин. Никакая операция не выполняет длинный цикл или массовый HTTP-вызов внутри одного административного запроса.

## 8. Ошибки и безопасность

- Все административные записи проверяют `manage_admitad_automation` и отдельный nonce.
- Campaign ID валидируется как положительное целое, существующее в локальном справочнике и уникальное среди термов.
- URL допускают только `http`/`https`; вывод всегда экранируется.
- Ошибки API не содержат токенов, Authorization headers и секретов.
- Ручные значения, предыдущий Deeplink и текущий логотип сохраняются при любой частичной ошибке.
- Публичная страница использует только локальные term-meta и transient/cache данные.

## 9. Проверки приёмки

- JS-тест подтверждает скрытие пустой буквенной группы, подсветку совпавшего фрагмента только в item и восстановление исходного текста.
- PHP-тесты подтверждают удаление ссылки вместе с её текстом и allowlist ручного HTML.
- Тесты term-editor подтверждают capability, nonce, видимость Campaign ID, ручной override и reset.
- Тесты контактов подтверждают заполнение только пустых значений, надёжное извлечение email/телефона и отсутствие автоадреса.
- Тесты несвязанных магазинов покрывают все четыре причины, быстрый save, неизвестный и дублирующий ID.
- Тесты Deeplink покрывают scope, URL/параметры, 401 refresh, unsupported/error fallback, fingerprint, сохранение старой ссылки и ручной override.
- Интеграционный тест подтверждает `href` через Admitad при видимом обычном домене и корректный `rel`.
- Полные существующие PHP/JS-наборы остаются зелёными; `style.css` пользователя и карточка промокода не изменяются.
